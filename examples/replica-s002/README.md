# 复刻案例：圆形头像卡片（ref.mp4 · s002）

第一个用 ShotPilot 走完「拉片 → 复刻包 → Remotion 代码 → 渲染比对 → 迭代」全流程的镜头。
2.17 秒，65 帧。这份记录比代码本身更有用：它说明了**怎么测、怎么验、哪里会骗你**。

## 结果

| 区域 | 第一轮误差 | 最终误差 | 说明 |
| --- | ---: | ---: | --- |
| 背景 | 0.00 | 0.00 | |
| 白环 | 0.62 | 0.66 | |
| 投影 | 6.63 | **0.68** | 发现它在旋转之后才降下来 |
| 黑边 | 14.02 | **1.51** | 逐列还原 |
| 字幕 | 15.82 | 11.85 | 卡在字体上，见「已知差距」 |

误差 = 逐帧平均绝对误差（0–255），65 帧取平均。全幅 SSIM 0.9763 → **0.9845**。

**但全幅 SSIM 在第一轮就已经「达标」了（0.976 > 0.90）**，而那时投影方向错了、黑边错了、字幕又细又淡。
大面积平坦背景会把分数撑高。**分区算误差 + 看差异图**才看得出真问题。

## 这个镜头是什么

**结构**（固定，代码画的）：

| 元素 | 实测参数 | 怎么测的 |
| --- | --- | --- |
| 画布 | 1280×720 @30fps，背景 `#FBFBFB` | 取样 |
| 黑边 | 左右各 4 列纯黑 + 1 列半灰 + 1 列白亮边 | 逐列读像素 |
| 外圆（白环） | 中心 (640.1, 357.0)，r=227 | 360 条射线找亮度变化最陡处，残差 0.27px |
| 内圆（头像区） | 中心 (639.7, 356.0)，r=183 | 浅蓝底外沿点最小二乘，残差 0.98px |
| 投影 | 偏移 45px，**顺时针旋转 1.422°/帧**，blur 26，α 0.25 | 逐帧极坐标拟合，每帧误差 0.4–0.8 |
| 字幕 | 白字 + 灰描边 + 挤出式硬投影，水平压窄 0.74 | 三轮扫参对齐墨迹框 |
| 换句 | 第 37 帧 | 逐帧量字幕宽度 |

**槽位**（换掉就是下一条视频）：`avatar` 头像、`avatarBg` 头像底色、`captions` 字幕时间轴、`captionStyle` 字幕样式。

## 迭代过程

每一轮都是：渲染 → 分区打分 → 看差异图 → 找原因 → 改。

**第 1 轮：摆位**。全幅 SSIM 0.976，已经「达标」。分区一看：投影 6.6、黑边 14、字幕 15.8。

**第 2 轮：黑边**。原片不是 5px 纯黑，而是 4 列纯黑 + 1 列半灰(78) + 1 列纯白——视频放大时锐化留下的振铃。逐列画出来，14.0 → 1.5。

**第 3 轮：字幕几何**。第一版字太高。只看纯中文的第二句最清楚：原片字高 46，复刻 50。三轮扫参（字号 × 压窄比例 × 位置）后墨迹框对齐到 ±2px。

**第 4 轮：字幕样式**。像素误差最优的那组又细又淡，一眼就不像。见下方「陷阱 4」。

**第 5 轮：外圆**。拟合投影时模型误差 0.69，实际渲染却是 7.7。查剖面发现环上方完全对上，问题在右侧：**外圆和内圆不同心**，第一版假设同心、半径也小了 2px。

**第 6 轮：投影在转**。修完外圆，投影误差依然 7.2。按帧拆开：第 1 帧 0.55，第 65 帧 13.4——**线性增长**。原片的投影在动。逐帧拟合发现偏移长度恒定 45px、方向匀速顺时针旋转，65 帧从正上方转到正右方。写成 `useCurrentFrame()` 驱动之后，6.6 → **0.68**，每帧都稳在 0.5–1.1。

## 四个陷阱（会发生在任何复刻上）

1. **别假设它是静止的。** 白环边缘全程不动，我就以为整个结构都静止，只拿第 1 帧拟合。
   结果投影在转。**拟合完要看误差随帧号怎么变**——线性增长就是有东西在动。
2. **别假设元素之间有关系。** 内外圆看起来同心，其实差 1px、半径也不是我以为的那样。每个元素**独立拟合**。
3. **找边缘别用阈值。** 「亮度 ≥253 算白环」会被抗锯齿骗，系统性低估半径。沿射线找**梯度最陡处**，不依赖任何阈值。
4. **像素指标在字形对不上时会偏爱「画得更淡」。** 两边字体不同，笔画天然错位，多画一笔灰就被扣两次分
   （原片有墨复刻没有 + 复刻有墨原片没有）。误差最低的候选反而最不像。**字形对不上时，按肉眼选。**

## 已知差距：字幕字体

原片字体不是思源黑体（笔画走向不同），复刻用的是 Noto Sans CJK SC。位置、大小、样式都对齐了，
但字形本身对不上——三轮扫参全部停在误差 10 附近，就是这个上限。

**如果你知道原片用的是什么字体**（剪映常用的抖音美好体、阿里巴巴普惠体之类），把字体文件放进 `public/`，
用 `@font-face` 或 Remotion 的 `loadFont` 注册后，改 `src/AvatarCard.tsx` 里 `CAPTION_DEFAULT.fontFamily`。
我没法验证能降到多少——这取决于字体是否真的对。

## 运行

```bash
npm install
cp <ShotPilot 复刻包>/clip.mp4 .      # 原片片段不在仓库里
npm run prepare-avatar                 # 从 clip.mp4 抠出头像素材（需要 pip install pillow numpy）
npm run studio                         # 浏览器里预览、拖时间轴
npm run render                         # 渲染 out.mp4
```

比对：

```bash
cd ../.. && pnpm compare --rendered examples/replica-s002/out.mp4 --original examples/replica-s002/clip.mp4 --fps 30 --diff diff.mp4
```

## 换成你自己的内容

改 `src/AvatarCard.tsx` 里的 `avatarCardDefaults`，或者渲染时传 `--props`（素材放在 `public/` 下）：

```bash
npx remotion render src/index.ts AvatarCard mine.mp4 --props='{
  "avatar": { "kind": "image", "src": "my-avatar.png" },
  "avatarBg": "#FFE4D6",
  "captions": [ { "from": 0, "text": "第一句" }, { "from": 40, "text": "第二句" } ]
}'
```

头像素材要求：460×460 带透明通道的 PNG，头像画在中心半径 183px 的圆里；想要破框效果就让头发越出去，越出部分保留、其余透明。
白环、旋转投影、背景、字幕样式全部自动沿用。时长不是 65 帧的话，同时改 `src/Root.tsx` 的 `durationInFrames`。

> 仓库是公开的，所以原片片段、从它抠出的头像帧、渲染结果都不入库（见 `.gitignore`）。
