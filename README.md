# ShotPilot 拉片工作台

把「在剪映里一刀一刀裁、来回跳转、没法标注」的拉片流程，变成一个可视化工作台：
**导入视频 → 自动切分镜 → 逐镜标注 → 导出笔记与复刻素材**。

产物同时面向两种用途：给人看的 Markdown 拉片笔记，和给 AI agent 用的结构化数据
（含词级时间戳，可对接 [hypit](https://github.com/hypit-ai/hypit) 的 SVML 工作流）。

## 为什么不是又一个剪辑软件

剪辑软件是为「产出成片」设计的，拉片是为「理解别人怎么拍」设计的，两者需求相反：

| 拉片真正需要的 | 剪辑软件的做法 |
| --- | --- |
| 一次性看到全部分镜 | 时间轴要来回拖 |
| 每个镜头挂结构化标注 | 只能改文件名或加马克点 |
| 标注能聚合统计、能导出 | 锁在工程文件里 |
| 分镜边界可反复调整而不丢标注 | 重切等于重来 |

## 快速开始

```bash
pnpm install
pnpm dev          # 打开 http://127.0.0.1:5174
```

在首页填视频的**绝对路径**，点「开始分析」。视频不会被复制或上传，项目只记录路径。

也可以走命令行批处理：

```bash
pnpm analyze --input /path/to/ref.mp4 --threshold 0.3
pnpm analyze --project <项目id> --export md --out 笔记.md
```

## 四项自动能力

| 能力 | 实现 | 是否花钱 |
| --- | --- | --- |
| **自动分镜切分** | ffmpeg `scene` 滤镜 + 最短镜头合并 | 本地，免费 |
| **逐词字幕** | 本地 WhisperX；或导入 SRT / whisper JSON | 本地，免费 |
| **BGM / 音频段落** | PCM 能量包络 → 起音检测 → 直方图投票估 BPM | 本地，免费 |
| **AI 标注景别/运镜** | 每镜抽 3 帧送视觉模型（OpenAI 兼容接口） | **按用量计费** |

前三项完全离线，装完就能用。第四项要自己配 key：

```bash
export SHOTPILOT_VISION_API_KEY=sk-...
export SHOTPILOT_VISION_BASE_URL=https://api.openai.com/v1   # 可换成任意兼容网关或本地模型
export SHOTPILOT_VISION_MODEL=gpt-4o-mini
```

### 两条关于 AI 标注的设计约束

1. **运镜必须多帧才判断得了**。单帧看不出推拉摇移，所以每个镜头抽首/中/尾三帧一起送。
2. **AI 只填空位，绝不覆盖人工标注**。人改过的字段会被标记为 `manual`/`ai-edited`，
   批量跑第二轮时跳过——不会把你的活儿冲掉。

## 标注维度

景别（10 档）· 运镜（12 种）· 构图（9 种，可多选）· 焦段（6 档）· 光线（12 种，可多选）·
机位（6 种）· 入点转场（9 种）· A-roll/B-roll 归类 · 复刻需求 · 元素 · 特效 · 逐镜备注。

全部做成受控枚举而非自由文本，为的是能用快捷键点选、能跨片聚合统计、能稳定喂回生成指令。

## 键盘操作

拉片是重复劳动，鼠标点选会让人坚持不下去。全程可键盘驱动：

| 键 | 作用 |
| --- | --- |
| `空格` | 播放 / 暂停 |
| `←` `→` | 上一个 / 下一个镜头 |
| `Enter` | 标记已审并跳下一个 |
| `S` | **在当前播放位置补一刀**（拆开漏检的镜头） |
| 面板按钮 | **在此镜头内细切** —— 只对选中镜头降低阈值重测 |
| `M` | **并入上一个镜头**（撤销多余的刀） |
| `1`–`0` | 景别 |
| `Q`–`P` | 运镜 |
| `A`–`L` | 构图 |
| `Z` `X` `C` `V` | A-roll / B-roll / 叠加层 / 字卡 |

## 复刻：把参考镜头还原成可复用的代码

这是「复刻」而不是「生成」——输入是你看中的参考镜头，第一指标是**像**。

```bash
# 打包所有标为 B-roll / 叠加层 / 字卡的镜头
pnpm replica --project <项目id> --all-broll --out ./replica-out

# 或只打一个镜头
pnpm replica --project <项目id> --shot s012
```

每个包里：

| 文件 | 作用 |
| --- | --- |
| `clip.mp4` | 原片这一段，**验收基准** |
| `frames/f0001.png …` | 逐帧序列（默认 10fps）。**动效分析必需**——单张关键帧看不出入场/移动/缩放 |
| `shot.json` | 画布尺寸、时长、标注、槽位定义、口播逐词时间戳（已转成镜头内相对时间） |
| `narration.txt` | 这一段的口播文案 |
| `README.md` | 给 agent 的三步法指令：摆位 → 动效 → 比对迭代 |

把包丢进 Remotion 项目目录，在那里开 Claude Code / Codex，让它读 `README.md` 开工。
**不绑定任何 agent，就是一个文件夹。**

### 比对：让复刻能收敛

没有可测量的目标，agent 改完只能问自己「像了吗」，于是越改越飘。

```bash
pnpm compare --rendered out.mp4 --original clip.mp4 --diff diff.mp4
```

逐帧算 SSIM，指出**最不像的几帧**和对应的帧文件，未达标时以退出码 2 结束（方便写进迭代脚本）。
`--diff` 额外生成三联对比视频：**左 原片 · 中 复刻 · 右 差异**，差异图里黑=一致、亮=错位。

判别力实测：同样是 12px 位移，纹理画面判 0.78（正确罚分），仅分辨率不同判 0.97（正确不罚）。

> ⚠️ **SSIM 是全帧平均，对纯色背景上的错位不敏感。**
> B-roll 的典型形态正是「文字压在纯色底上」——标题偏 20px，但 80% 画面是没变化的背景，
> 分数照样能到 0.97 蒙混过关。**这种情况一定要看 `--diff` 的差异视频**，别只信数字。

## 导出

| 格式 | 用途 |
| --- | --- |
| **Markdown 拉片笔记** | 给人看：结构速览 + 逐镜拆解，可直接贴进笔记软件 |
| **handoff JSON** | 给 agent 用：完整结构化标注 + 词级时间戳。**复刻时优先读这个** |
| **SVML** | hypit 对接草稿，见下方说明 |

### 关于 SVML 导出的诚实说明

**已验证**（依据 hypit 官方 `@hypit/markup` 文档样例）：处理指令 `<?svml using="@hypit/markup@1"?>`、
`<svml>` 根元素、`<import>` 必须先于 body、`<script>` 分段、`<ROLE>文本` 角色提示。

**草稿**：镜头级摄影标注（景别/运镜/光线等）在 hypit 公开文档里**没有对应词汇表**——
`@hypit/markup` 本身不含脚本/媒体/视频词汇，那些来自导入的包，而这些包的词汇表未公开。
所以这部分目前写成 `shotpilot:` 前缀的 meta 属性。

拿到官方词汇表后，只需改 `src/export/svml.ts` 里的 `SHOT_VOCAB` 一处即可对齐。
在那之前，**别把这份 SVML 当成 hypit 能直接消费的格式**——用 handoff JSON。

## 已知限制

- **人声 / 音乐的区分依赖转写结果**。没跑转写时只能给出「有声 / 静音」两档，
  有声段一律标为音乐，项目文件的 `audio.method` 字段会如实写明。
- **BPM 估算对鼓点清晰的流行/电子 BGM 有效**，氛围音乐会测不出，此时返回 `null` 而不是编一个数字。
- **SRT 导入没有真实词级时间**，按字符数均摊，导出时会标注为非真实对齐——别拿它做卡点。
- **AI 标注的准确率未做系统评测**。当前是能跑通的实现，不是调优过的结果，务必逐镜复核。
- **全局一个阈值永远调不对，因为同一条片子里不同内容的场景分数差一个数量级。**
  口播段落人一动整帧都在变，分数很高；录屏演示只有鼠标和局部 UI 在变，占整帧不到 5%，
  分数被稀释到 0.0x 量级。实测一条 2:09 的视频，一段 38 秒的录屏演示在阈值 0.3 下
  一刀未切，降到 0.2 仍然一刀未切——因为真实分数根本不在这个区间。
  所以设计上不指望阈值调到完美，而是三层兜底：
  全局自动切 → 对个别镜头「细切」降阈值重测 → 剩下的用 `S` 手动补。
- 场景检测阈值对不同片子差异很大，所以内置了「重新切分」并保证标注按时间重叠迁移。
